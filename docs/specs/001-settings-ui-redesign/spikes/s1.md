# Spike S1 — Tailwind version, scoping, specificity, portals (T-014)

Investigative spike feeding **ADR-014**. It settles the items ADR-001, ADR-007 and ADR-009
left open: **D1** (Tailwind version), **D2** (utility prefix + exact syntax), the
**scope-selector syntax**, the **portal-host placement** and the **exact scoped-base rule
list**. No production code lands — only this file and ADR-014.

- Date: 2026-10-08. Node 24.5.0, npm 11.5.1 (ADR-010 removes the runtime as a constraint:
  both Tailwind v4 and v3.4 run on Node 24, so **D7 is not a blocker**).
- Throwaway builds done in an isolated scratchpad (never in the repo tree). Real
  `tailwindcss` installs: **v3.4.17** and **v4.3.3**.
- Browser probes run with the repo's Playwright chromium against static harnesses; the
  wp-admin stacking numbers come from the running wp-env WordPress core CSS.

## D1 — Tailwind version: **v3.4** (reject v4)

### Method

One identical 44-utility fixture (a button, an input, a select, plus the logical/RTL set
`ms-* me-* ps-* pe-* text-start rounded-s/e-* border-s/e-* gap-* rtl:-scale-x-100`), built
twice with Preflight suppressed and prefix `tw`, adjusting only the per-version syntax
(`tw-class` for v3, `tw:class` for v4). Minified column is cssnano (v3 `--minify` is
cssnano; v4 `--minify`).

### CSS size per variant (real builds)

| Build | expanded | minified | structure |
|---|---:|---:|---|
| v3.4.17 — utilities only, **unscoped** | 3 604 B | 3 093 B | 45 flat rules, no `@layer`, **no global selectors** |
| v3.4.17 — utilities, **scoped** `important: ':is(#complianz, #complianz-portal)'` | 5 179 B | 4 623 B | same rules, each prefixed with the scope `:is()` (1,1,0), **no `!important`** |
| v4.3.3 — theme+utilities, Preflight suppressed, **unscoped** | 7 352 B | 5 954 B | native `@layer theme/utilities` + `@layer properties`; `:root,:host{--tw-*}` theme block; **global `*,::before,::after,::backdrop{--tw-*}`** rule; **21 global `@property --tw-*`** registrations |

For the same utilities, minified v4 is **~1.9×** v3 (5 954 vs 3 093 B). The gap is
structural (theme variables, `@property` scaffolding, layer wrappers), not extra utilities,
and it grows the floor regardless of how few utilities are used.

### The decisive finding — cascade layers lose to unlayered wp-admin CSS

wp-admin ships its form and admin CSS **unlayered**. In the CSS cascade, **unlayered normal
declarations beat any `@layer` normal declaration regardless of specificity** (layer order
is resolved before specificity). Tailwind **v4 emits its utilities inside `@layer
utilities` by default** and offers no first-class switch to turn that off. Browser probe
(chromium, `getComputedStyle`), identical scope-ID specificity (1,1,0) on both utilities,
competing against an unlayered `input[type=text]{padding:0 8px}` (forms.css shape, 0,1,1):

| element | rule form | `padding-left` | verdict |
|---|---|---:|---|
| flat utility (v3 model) | `:is(#complianz,#complianz-portal) .tw-px-3` (unlayered) | **12px** | utility **beats** forms.css ✓ |
| layered utility (v4 model) | `@layer utilities { :is(#complianz,#complianz-portal) .tw-px-3 }` | **8px** | utility **loses** to unlayered forms.css ✗ |

The v4 layered utility is defeated by wp-admin **despite identical specificity** — exactly
the failure ADR-001 warned about ("If S1 picks cascade layers instead, it must prove the
same order against unlayered wp-admin CSS"). Recovering it in v4 would mean `important: true`
(global `!important` on every utility), which then overrides the `data-cmplz-isolate`
vendor CSS and breaks the isolate zones. Not acceptable.

### Secondary v4 problems against ADR-001 / FR-002 ("no global, scoped only")

- v4's output carries a **global universal rule** `*,::before,::after,::backdrop{--tw-*:…}`
  (property defaults, inside an `@supports`) and **21 global `@property --tw-*`**
  registrations. These touch every element on the page and cannot be scoped to
  `#complianz` without breaking the utilities that read them. v3 with `preflight:false`
  emits **zero** global/universal selectors (`grep` for `^\*|:root|^html|^body` → 0).
- Scoping v4 is harder: `important:` is not a scope hook in v4, so scoping needs
  `postcss-prefix-selector` over output that contains `@layer` blocks, a global `*` rule
  and `@property` at-rules — none of which prefix cleanly. v3's `important:
  ':is(#complianz, #complianz-portal)'` scopes every utility to 1,1,0 in one config line,
  with no extra plugin and no `!important` (verified: `:is(#complianz, #complianz-portal)
  .tw-me-2{margin-inline-end:.5rem}`).

### Decision

**Tailwind v3.4** (pin a current 3.4.x, e.g. 3.4.17). It produces flat, unlayered,
ID-scoped utilities that win against unlayered wp-admin CSS by ordinary specificity; it
composes with the existing `@wordpress/postcss-plugins-preset` + cssnano pipeline (ADR-009)
with no layer gymnastics; it emits no global rules with Preflight off; and 3.3+ already
ships the logical utilities ADR-007 needs. v4's speed/modern-config gains do not outweigh
the coexistence breakage against unlayered wp-admin, which is the whole point of the scope
contract. Node 24 keeps v4 available later, so this is reversible if wp-admin ever adopts
cascade layers.

## D2 — utility prefix + exact syntax: **`tw-` class-prefix (v3 form)**

- Config: `prefix: 'tw-'`. Utilities read `tw-bg-blue-600`, `tw-rounded-md`, `tw-ms-2`.
- Variants come **before** the prefix: `hover:tw-bg-blue-700`, `focus:tw-ring-2`,
  `disabled:tw-opacity-50`, and the RTL escape hatch `rtl:tw--scale-x-100` (ADR-007).
- The v4 `tw:`-variant form (`tw:bg-blue-600`, `tw:hover:bg-blue-700`) is **rejected** with
  v4. `settings/scripts/check-physical-utilities.js` (ADR-007 / T-016) therefore strips the
  **`tw-`** prefix (and a leading `-`, and variant segments) — not `tw:`.

## Scope-selector syntax: **`:is(#complianz, #complianz-portal)` — CONFIRMED**

- Specificity of `:is(#id, #id)` is **1,0,0**; with a utility class the utility is **1,1,0**
  (beats forms.css `input[type=text]` 0,1,1 and legacy `.cmplz …`); the base (scope +
  `:where()`) is **1,0,0** (above wp-admin element rules, below utilities).
- The selector names **both** placements: the portal host sits inside `#complianz` in the
  normal case, but falls back to `#complianz-portal` at the end of `<body>` (below), which
  is outside `#complianz` — so the scope must match either. Confirmed, no change.

## Exact scoped-base rule list

Specificity **1,0,0** = scope ID + `:where()`. Matches **only `data-cmplz-ui`** subtrees.
**Excludes `data-cmplz-isolate` INSIDE the `:where()`** via the exclusion token
`:not([data-cmplz-isolate] *):not([data-cmplz-isolate])` (descendants of a zone **and** the
zone element itself). ADR-001 is explicit that a `:not()` **outside** `:where()` would lift
the base to 1,1,0 and wrongly beat the utilities — so the exclusion lives inside `:where()`.

```css
/* B1 — box-sizing + border reset (utilities assume Preflight's border defaults) */
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] *:not([data-cmplz-isolate] *):not([data-cmplz-isolate])),
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] *:not([data-cmplz-isolate] *):not([data-cmplz-isolate]))::before,
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] *:not([data-cmplz-isolate] *):not([data-cmplz-isolate]))::after {
  box-sizing: border-box; border-width: 0; border-style: solid; border-color: currentColor;
}
/* B2 — root typography, ONE rule on the two inner wrappers (FR-003) */
:is(#complianz, #complianz-portal) :where(#complianz-app-root[data-cmplz-ui], #complianz-portal-root[data-cmplz-ui]) {
  font-size: 14px; line-height: 1.5; color: #1e1e1e; -webkit-font-smoothing: antialiased;
}
/* B3 — form controls inherit font (Preflight replacement) */
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] :is(button,input,select,textarea,optgroup):not([data-cmplz-isolate] *):not([data-cmplz-isolate])) {
  font: inherit; color: inherit; margin: 0;
}
/* B4 — button reset */
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] button:not([data-cmplz-isolate] *):not([data-cmplz-isolate])) {
  cursor: pointer; background-color: transparent; background-image: none;
}
/* B5 — replaced elements (optional, keeps images sane without full Preflight) */
:is(#complianz, #complianz-portal) :where([data-cmplz-ui] :is(img,svg,video,canvas,audio,iframe,embed,object):not([data-cmplz-isolate] *):not([data-cmplz-isolate])) {
  display: block; max-width: 100%; height: auto; vertical-align: middle;
}
```

Border defaults (B1) matter: Tailwind v3's `border` utility sets only `border-width`, so
without a base `border-style: solid` default the utility draws nothing — this is why a
zero-specificity / no base was rejected in ADR-001.

### Browser proof of the contract (chromium, computed styles)

| element (inside `#complianz [data-cmplz-ui]`) | what it carries | result | contract |
|---|---|---|---|
| input + `.tw-px-3` | utility vs unlayered forms.css | `padding-left: 12px` | utility (1,1,0) **beats** forms.css ✓ |
| input, no utility | base border vs forms.css | `border-top-width: 2px` | base (1,0,0) **beats** forms.css 0,1,1 ✓ |
| input inside `[data-cmplz-isolate="preview"]` | base must NOT reach it | `border-top-width: 1px` (forms.css) | isolate **excluded** ✓ |
| `button.tw-bg-blue-600` | utility vs legacy `button{all:unset}` | `background: rgb(37,99,235)` | utility **beats** legacy global reset ✓ |
| `button.button.button-primary` (WP) | our scoped CSS must not touch it | `background: rgb(246,247,247)`, `padding-left: 10px` | WP button **unaffected** ✓ |

The isolate-exclusion token was corrected during the spike: an earlier form
(`[data-cmplz-ui]:not([data-cmplz-isolate]) input`) wrongly let the base reach an isolated
input (checked only the ancestor zone-marker, not the input's own isolate ancestry); the
token above (`*:not([data-cmplz-isolate] *):not([data-cmplz-isolate])`) fixes it and is the
one to ship.

## Portal-host placement

**Decision:** render overlays into `#complianz > #complianz-portal >
#complianz-portal-root[data-cmplz-ui]` — a **sibling of `#complianz-app`**, inside
`#complianz`. Fallback: append `#complianz-portal` to the **end of `<body>`** if any
ancestor between `#complianz` and `<body>` has a used `transform`/`filter`/`perspective`/
`contain` that would trap `position: fixed` (that is why the scope selector also names
`#complianz-portal`).

Rationale, with evidence:

- The settings app wrapper uses an off-canvas `translateX` below 1800px (§4.5), which
  creates a containing block. Making the portal a **sibling** of `#complianz-app` (not a
  descendant) keeps Radix's `position: fixed` overlays anchored to the **viewport**.
  Harness (chromium): with `#complianz-app` transformed, a dialog in the sibling portal
  resolves to `top:4, left:4` (viewport-anchored, not clipped).
- Stacking: real wp-admin z-index ceiling from the running wp-env core CSS —

  | surface | z-index |
  |---|---:|
  | `#wpadminbar` | 99999 |
  | admin menu (`#adminmenuwrap`, responsive auto-fold) | up to 100000 |
  | `.media-modal-backdrop` / `.media-modal` | 159900 / 160000 |
  | WP media sub-layers / pointers / thickbox | 250000 – 600000 |

  Harness confirms a portal overlay at `z-index: 100000` is the top element over the admin
  bar (`elementFromPoint` → the overlay, not `#wpadminbar`). **Ship the portal root at
  `z-index: 100001`** (strictly clears the admin bar 99999 and the responsive menu 100000)
  **and keep it below the WP media modal (160000)** so a media modal opened from a field
  still sits on top. Give the root `isolation: isolate` so app overlays stack among
  themselves without leaking a stacking context to wp-admin. react-toastify (default
  z-index 9999) and a Shepherd step (`.shepherd-element`, default 9999) render into this
  host and inherit its context, so they clear the chrome too.
- Radix Dialog/Popover/Tooltip all accept a `container` prop (ADR-001's shared
  `PortalContainer` → `#complianz-portal-root`); react-shepherd takes a mount/`modalContainer`
  target. All four therefore render inside the scoped host and receive the scoped base +
  utilities (the host carries `data-cmplz-ui`).

### CKEditor `.ck-body-wrapper` exception (drafted)

CKEditor appends its balloon/dropdown/dialog panels to a body-level `.ck-body-wrapper`,
**outside** `#complianz`/`#complianz-portal`, so our scoped CSS cannot reach them (correct —
they use CKEditor's own runtime CSS) **but** their default z-index (`--ck-z-modal` ≈ 1000)
sits **below** our portal (100001); a CKEditor dropdown opened from an editor inside a Radix
dialog would be clipped behind it. The one documented **unscoped** exception (ADR-001) lifts
them, shipped in the single `index.css`:

```css
/* Unscoped exception (ADR-001/014): CKEditor panels live at body-level .ck-body-wrapper,
   outside the scope; lift them above #complianz-portal-root (100001) so panels opened from
   an editor inside a dialog are not clipped. */
.ck-body-wrapper { --ck-z-default: 1; --ck-z-panel: 100002; --ck-z-modal: 100002; }
.ck-body-wrapper .ck.ck-balloon-panel,
.ck-body-wrapper .ck.ck-dialog-overlay { z-index: 100002; }
```

The WP media modal stays out of scope (ADR-001); nothing here raises anything above it.

## Coexistence evidence (summary)

With the spike entry CSS **loaded on stock wp-admin** (compiled into the enqueued admin
stylesheet for the proof run):

- A prefixed/scoped/Preflight-less button, input and select render inside a `data-cmplz-ui`
  container and their utilities beat `forms.css` and legacy `admin.css` (table above).
- A Tailwind button next to — and one carrying — WP `.button button-primary` leaves the WP
  button untouched (`#f6f7f7` fill, 10px padding unchanged); the scoped utilities apply
  only through the `tw-` class + scope, not to WP classes.
- An input rebuilt inside a legacy ID-prefixed container confirms ADR-005's narrow-removal
  rule suffices: the base (1,0,0) + utility (1,1,0) clear the remaining legacy element/`.cmplz`
  rules without needing wider deletions.

## Proof run

Command (run **once**, per T-014):

```
npm run build:all && npx wp-env start && \
  npm run e2e -- --project=admin tests/e2e/admin/visual.spec.js tests/e2e/admin/isolation.spec.js
```

The spike CSS compiled into all four enqueued admin stylesheets (`admin.css`,
`admin.min.css`, `rtl/admin.css`, `rtl/admin.min.css`), so the settings page served it
during the run. Result (one run, as mandated): **7 passed, 1 failed, 1 did not run.**

- **Isolation — blocking signals: PASS.** `banner preview element baselines per layout`
  (26.3s) and `wp-admin chrome baseline on a Complianz screen` (1.1s) both passed with the
  spike CSS loaded — the `data-cmplz-ui` restriction and `data-cmplz-isolate` exclusion mean
  the scoped/prefixed/Preflight-less CSS disturbs neither the banner preview nor wp-admin
  chrome. `website banner element baselines` also passed. These are the meaningful signals
  and they are green.
- **Isolation — media-modal test: FAILED, but PRE-EXISTING and NOT caused by the spike.**
  `WordPress media modal baseline` fails at `uploader.click()` (isolation.spec.js:254)
  because the Radix select option overlay (`.cmplz-select-group__item`) intercepts the
  click — the modal-open interaction, not the (non-blocking) screenshot. It reproduced 2/2
  with the spike, then **also failed identically on the clean committed tree with no spike
  CSS at all** (control run). The spike CSS cannot match `.cmplz-select-group__item` (no
  `tw-` class, no `data-cmplz-ui` ancestor), so it is exonerated by construction and by the
  control. The maintainer already classifies the media-modal shot as timing-sensitive /
  non-blocking (T-013); here it is the interaction that flakes, independent of this spike.
  The serial-mode abort then left `non-Complianz admin screen baseline` as "did not run".
- **Visual spec (full-screen, NON-BLOCKING by maintainer decision): PASS, drift recorded.**
  `every smoke screen is visually stable` (4.8m) passed while recording drift on **7
  screens**: `#dashboard` (1440/768), `#wizard/cookie-descriptions` (1440/768),
  `#banner/banner-general` (1440), `#banner/banner-texts` (1440),
  `#integrations/integrations-plugins` (768). These are the dynamic-content / random-
  placeholder-width screens the maintainer made non-blocking (T-002 notes placeholder widths
  are random per build; the proof rebuilds, so these drift on any rebuild). No baselines
  were regenerated; drift is recorded, not chased.

Because nothing in today's app carries `data-cmplz-ui` or a `tw-` class, loading the
scoped/prefixed/Preflight-less CSS is a no-op on the rendered DOM — precisely the isolation
guarantee being validated, and confirmed by the two blocking isolation signals passing.

## Reconciliation of the ADRs' open notes (feeds re-plan gate R1)

- **ADR-001** — "pending S1" items are now settled here and in ADR-014 (version v3.4;
  prefix `tw-`; scope `:is(#complianz, #complianz-portal)`; portal inside `#complianz`,
  body fallback; the base rule list and isolate-exclusion token above). The experiments
  **confirm** ADR-001's Decision and specificity contract in every respect — including its
  explicit warning that the isolate exclusion must sit inside `:where()` and that cascade
  layers must be proven against unlayered wp-admin (they fail). **Nothing overturns
  ADR-001;** its Decision section is left untouched and reconciled by cross-reference in
  ADR-014.
- **ADR-007** — D1 resolves to v3, whose logical utilities (3.3+) are confirmed in the
  builds (`margin-inline-start/-end` emitted); the physical-utility check strips the `tw-`
  prefix (not `tw:`). No change to ADR-007.
- **ADR-009** — the zone prefix uses the confirmed `:is(#complianz, #complianz-portal)`
  scope; whether `postcss-prefix-selector` + `postcss-rtlcss` compose with the chosen
  **v3.4** + PostCSS/cssnano pipeline is **S2's** check (T-016), now unblocked by this
  version choice. No change to ADR-009.

**R1 input:** no finding overturns ADR-001/007/009. The only correction is internal to this
spike (the isolate-exclusion token). The one decision that would have forced a re-plan —
picking cascade layers / v4 — is explicitly rejected with browser evidence.
