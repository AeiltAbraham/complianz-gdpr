## 1 — Entry-CSS pipeline: Tailwind + the re-added WP preset + production cssnano

### The throwaway `postcss.config.js`

```js
const tailwindcss = require('tailwindcss');
const wpPreset = require('@wordpress/postcss-plugins-preset'); // ARRAY: [postcss-import, autoprefixer]
const isProd = process.env.NODE_ENV === 'production';

module.exports = {
  plugins: [
    tailwindcss('./tailwind.config.js'),
    ...wpPreset,                                              // RE-ADDED, must be spread
    ...(isProd ? [require('cssnano')({ preset: 'default' })] : []),
  ],
};
```

```js
// tailwind.config.js (throwaway; the ADR-014 setup)
module.exports = {
  content: ['./src/**/*.{js,jsx}'],
  prefix: 'tw-',
  important: ':is(#complianz, #complianz-portal)',
  corePlugins: { preflight: false },
};
```

### Finding — the WP preset must be **re-added and spread**

`@wordpress/scripts` injects `@wordpress/postcss-plugins-preset` for us; the moment the app
ships its **own** `postcss.config.js` (needed for Tailwind), wp-scripts' default config is
replaced, so the preset drops out unless we add it back. **Gotcha confirmed in the build:**
the preset's module export is an **array** `[postcss-import, autoprefixer]`, not a plugin —
listing it directly throws `TypeError: Invalid PostCSS Plugin found at: plugins[1]`. It must
be **spread** (`...wpPreset`). With it spread, the build is clean and autoprefixer runs
(e.g. it emitted `-webkit-user-select` next to `user-select` in the combined output below);
`postcss-import` inlines `@import`s (see §4).

### Finding — a lazy-chunk-only utility still lands in the single entry `index.css`

Two sources: `src/index.js` (eager) uses `tw-ms-4 tw-pe-2 tw-text-start tw-rounded-s-lg
tw-gap-3 tw-bg-blue-600`; `src/Lazy/LazyChunk.js` is reached **only** through a dynamic
`import()` (a separate webpack chunk) and is the **sole** user of `tw-me-8` (plus
`rtl:tw--scale-x-100`, `tw-border-s`). Tailwind generates CSS by **content-scanning every
file in `content`**, not per webpack chunk, so the lazy chunk's utility appears in the one
entry CSS. In the minified entry `index.css`:

```css
:is(#complianz,#complianz-portal) .tw-me-8{margin-inline-end:2rem}
```

This is exactly the single-file model ADR-007/FR-016 needs: one `index.css` carries utilities
for every chunk, so a lazily-loaded component is never missing its (LTR **and** RTL) styles —
the defect ADR-007 records for today's per-chunk `-rtl.css` siblings.

### Finding — scope applied with no `!important`; cssnano minifies

Generated rules (dev build, before cssnano) — scoped to 1,1,0 via the `important:` selector,
**zero** `!important` in the file:

```css
:is(#complianz, #complianz-portal) .tw-ms-4       { margin-inline-start: 1rem }
:is(#complianz, #complianz-portal) .tw-pe-2       { padding-inline-end: 0.5rem }
:is(#complianz, #complianz-portal) .tw-rounded-s-lg { border-start-start-radius:.5rem; border-end-start-radius:.5rem }
:is(#complianz, #complianz-portal) .tw-border-s   { border-inline-start-width: 1px }
:is(#complianz, #complianz-portal) .tw-text-start { text-align: start }
```

Entry CSS size (base + components + utilities for this small fixture set):
**3 902 B expanded → 3 155 B minified** by cssnano `preset: 'default'`. `grep -c '!important'`
→ 0, confirming S1's "scope without `!important`".

## 2 — Logical utilities and `rtl:` variants on the single `index.css`

ADR-007 writes layout with logical utilities and keeps `rtl:`/`ltr:` only where logical
properties cannot express the intent. Both are confirmed present in v3.4 from the single
build above:

- **Logical utilities** emit logical CSS: `tw-ms-*`→`margin-inline-start`,
  `tw-me-*`→`margin-inline-end`, `tw-pe-*`→`padding-inline-end`,
  `tw-rounded-s-lg`→`border-start-start-radius`/`border-end-start-radius`,
  `tw-border-s`→`border-inline-start-width`, `tw-text-start`→`text-align: start`. No
  `is_rtl()` switch and no second stylesheet are involved.
- **The `rtl:` escape hatch** compiles to a direction-gated selector in the **same** file:

  ```css
  :is(#complianz, #complianz-portal) .rtl\:tw--scale-x-100:where([dir="rtl"], [dir="rtl"] *) {
    --tw-scale-x: -1; transform: …scaleX(var(--tw-scale-x))… ;
  }
  ```

WordPress sets `dir="rtl"` on `<html>` for a `he_IL` admin, so the logical properties resolve
RTL automatically and the `:where([dir="rtl"], …)`-gated `rtl:` rules activate — one
`index.css` serves both directions, no `index-rtl.css`. Per the T-016 allowance, this is
verified from the generated CSS and the `dir="rtl"` gating mechanism; the full `he_IL`
`admin-rtl` e2e project (ADR-007 "Verification") runs in the e2e suite, not in this spike.

## 3 — Enqueue probe: no PHP warning in an unbuilt checkout

Today's `class-admin.php:218` enqueues with `filemtime( $path )` as the cache-buster. The new
entry CSS lives at `settings/build/index.css`, which does **not** exist in a fresh, unbuilt
checkout (`npm ci` + build not yet run) — and `filemtime()` on a missing file raises a
warning. Probe (PHP 8.5, `E_ALL`), the **actual** message:

```
PHP Warning:  filemtime(): stat failed for …/settings/build/index.css in … on line 11
returned: false
```

A `file_exists()` guard removes it cleanly:

```php
$ver = file_exists( $path ) ? filemtime( $path ) : CMPLZ_VERSION; // no warning
```

So the entry-CSS enqueue must be guarded (`file_exists`/`filemtime`) before it ships; **T-021
formalises this guard**. Recorded here as the build/enqueue coexistence hazard S2 surfaces.

## 4 — Vendor pipeline prototype on react-date-range (ADR-009)

Goal: run `postcss-prefix-selector` + `postcss-rtlcss` on `styles/vendors/` **only**, scoping
every imported selector to the widget's zone and emitting `[dir="rtl"]` variants in the same
file, and prove it **composes** with the ADR-014 Tailwind setup.

### The throwaway vendor-only config

```js
const prefixer = require('postcss-prefix-selector');
const rtlcss = require('postcss-rtlcss').default || require('postcss-rtlcss');
const ZONE = ':is(#complianz, #complianz-portal) [data-cmplz-isolate="date-range"]';

module.exports = {
  plugins: [
    prefixer({
      prefix: ZONE,
      transform(prefix, selector, prefixedSelector) {
        // :root / html / body carry the library's document-level styles → land them on the zone
        if (selector === ':root' || selector === 'html' || selector === 'body') return prefix;
        return prefixedSelector;
      },
    }),
    rtlcss(),
  ],
};
```

Run on the **real** `react-date-range/dist/styles.css` (plus a small appended
`:root{…}/html{…}/body{…}/@keyframes` block, representing libraries such as react-toastify
that set custom properties on the document root):

- **Zone prefixing** — every selector gets the zone selector:
  `:is(#complianz, #complianz-portal) [data-cmplz-isolate="date-range"] .rdrCalendarWrapper { … }`.
- **`:root`/`html`/`body` → the zone element** (ADR-009), carrying the library's doc-level
  declarations, with **no bare `:root`/`html`/`body` left**:
  ```css
  :is(#complianz, #complianz-portal) [data-cmplz-isolate="date-range"] { --rdr-accent:#2d6cdf; }
  :is(#complianz, #complianz-portal) [data-cmplz-isolate="date-range"] { color-scheme: light; }
  :is(#complianz, #complianz-portal) [data-cmplz-isolate="date-range"] { --rdr-font: inherit; }
  ```
- **`[dir="rtl"]` variants in the same file** — directional rules are flipped, logical/
  symmetric ones are not:
  ```css
  [dir="ltr"] …[data-cmplz-isolate="date-range"] .rdrDateDisplayItem + .rdrDateDisplayItem { margin-left: 0.833em; }
  [dir="rtl"] …[data-cmplz-isolate="date-range"] .rdrDateDisplayItem + .rdrDateDisplayItem { margin-right: 0.833em; }
  ```
- **`@keyframes` names preserved** — `@keyframes rdrPulse { … }` is untouched (prefixer does
  not rewrite keyframe selectors), so `animation-name` references still resolve.

### Composition with the Tailwind pipeline — one `index.css`

The vendor pre-step writes a plain, already-scoped CSS file; the entry imports it
(`@import "./vendors/date-range.built.css";`) and the main pipeline's **`postcss-import`**
(from the re-added WP preset) inlines it. Tailwind only processes the `@tailwind` directives
and leaves the vendor rules alone. The one minified `index.css` then carries **both**:

```css
:is(#complianz,#complianz-portal) .tw-ms-4{margin-inline-start:1rem}                       /* Tailwind utility */
:is(#complianz,#complianz-portal) [data-cmplz-isolate=date-range] .rdrCalendarWrapper{…}   /* inlined, zone-scoped vendor */
```

`grep -c '@import'` on the output → **0** (fully inlined). Both PostCSS plugins are build-time
only and are not shipped. **ADR-009's pending composition check is settled: the vendor step
composes cleanly with the ADR-014 Tailwind + re-added-WP-preset + cssnano pipeline.**

## 5 — The physical-utilities check (`check-physical-utilities.js`) — the real deliverable

ADR-007's enforcement script, the only production file this task lands (CommonJS, Node 24, no
deps, matching the repo's other `scripts/*.js`). It scans `settings/src/**/*.{js,jsx}` by
default (accepts path args), extracts class tokens from `className` (string, `{'…'}`, template
literals) and from `clsx()/classnames()/cva()` calls and their variant maps, and for each
token strips the `tw-` prefix (ADR-014; **`tw-`**, not `tw:`), a leading `-` (negatives, either
side of the prefix) and the variant segments (the chain up to the last `:` outside `[...]`),
then fails on a banned physical utility **unless** the variant chain carries `rtl:`/`ltr:`.

**Banned family enforced** (ADR-007 §4.6, the full list): `ml-*`/`mr-*`, `pl-*`/`pr-*` and
their `scroll-` forms (`scroll-ml/mr/pl/pr-*`); `left-*`/`right-*` insets; `text-left`/
`text-right`; `float-left`/`float-right`; `clear-left`/`clear-right`; `border-l*`/`border-r*`;
corner radii `rounded-l/r/tl/tr/bl/br(-*)`; `space-x-*`; `divide-x-*`; left/right
`origin-*`; `bg-left*`/`bg-right*`; and left/right gradient directions
`bg-gradient-to-{l,r,tl,tr,bl,br}`. Logical replacements (`ms/me`, `ps/pe`, `start/end`,
`text-start/-end`, `rounded-s/e*`, `border-s/e`, `gap-*`, `space-y`/`divide-y`, `rounded-t/b`,
`bg-top/bottom`, `to-t/b`) and Tailwind colours (`border-red-*`, `bg-center`, …) pass.

### `--self-test` (probe-at-build, introduced by this task)

The script bundles in-memory fixtures (no extra files) and asserts the checker's behaviour.
**Red evidence:** with the `BANNED` list emptied, the self-test fails
(`expected a violation for 'ml-4' … got none`, exit 1). **Green:** the full script passes.

```
$ node settings/scripts/check-physical-utilities.js --self-test
self-test: PASS (6 fixtures)
  banned `ml-4` is flagged; its `rtl:ml-4` escape, the logical `ms-4`,
  `clsx('tw-ps-2', { 'tw-me-2': on })` and `rtl:tw--scale-x-100` all pass.
  sample failure message (probe-at-build — what a real violation prints):
    banned.js:2:38  ml-4  — physical margin ml-*/mr-* (use ms-*/me-*)
```

The fixtures prove: a banned `ml-4`-style token exits non-zero naming **file:line:col** and
the token; its `rtl:`-variant form (`rtl:ml-4`) and the logical replacement (`ms-4`) exit 0;
prefix stripping catches `tw-pr-2`; a `clsx()` call with a variant-map object
(`{ 'tw-me-2': on }`) is read; and the escaped negative `rtl:tw--scale-x-100` passes.
